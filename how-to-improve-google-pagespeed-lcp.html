How to Improve Google PageSpeed & Fix Largest Contentful Paint (LCP)

A complete technical optimization roadmap: diagnosing slow LCP elements, eliminating render-blocking CSS/JS, minimizing Time to First Byte (TTFB), and achieving 90+ Core Web Vitals on mobile and desktop.

Performance Engineering By Shashi Kumar Updated November 2026 9 Min Read

If your website scores in the red or orange on Google PageSpeed Insights, you are not alone. Millions of websites struggle with slow loading times, sluggish interaction responsiveness, and layout instability. However, chasing a synthetic 100/100 score in isolation is missing the point: what truly matters for your business is how quickly real visitors experience your website.

Central to Google’s page experience assessment is Largest Contentful Paint (LCP), which measures how long it takes for the primary visible content on your page (such as a hero banner or main heading) to render on the screen. In this engineering guide, SK Digital breaks down exactly how to improve Google PageSpeed, eliminate render-blocking assets, and achieve sub-2.5 second LCP.

1. What Is Largest Contentful Paint (LCP)?

Largest Contentful Paint (LCP) is one of Google's three core performance metrics. It tracks the point in the page load timeline when the main content block has likely rendered. On typical websites, the LCP candidate is:

  • An <img> element (such as an e-commerce product hero image or homepage background banner).
  • An image element inside an <svg> container.
  • A video poster image thumbnail.
  • A large block-level text element (such as a prominent <h1> title).

2. The Core Web Vitals Benchmark Hierarchy

Core Web Vital Target Threshold What It Measures
Largest Contentful Paint (LCP) ≤ 2.5 seconds Perceived visual loading speed of primary content.
Interaction to Next Paint (INP) < 200 milliseconds Main-thread UI responsiveness to clicks, taps, and keyboard inputs.
Cumulative Layout Shift (CLS) < 0.1 score Visual stability (preventing accidental clicks as fonts/banners load).

3. Step 1: Diagnose Real Field Data vs. Lab Data

When running PageSpeed Insights, distinguish between:

  • Lighthouse Lab Diagnostics: A synthetic test run on an emulated mid-tier mobile phone on a throttled 4G network. Excellent for debugging issues.
  • Chrome User Experience Report (CrUX): Aggregated field data collected from millions of real Chrome visitors over 28-day rolling periods. Google’s search algorithms rank your website based on this field data.

4. Step 2: Identify Your Exact LCP Element

Open Chrome DevTools (<kbd>F12</kbd>), switch to the Performance tab, and record a page reload. Expand the Timings lane and click on the LCP flag. DevTools will immediately highlight the exact DOM element in the viewport that triggered LCP.

5. Step 3: Optimize and Preload the LCP Image

If your LCP element is an image, implement these 4 developer fixes immediately:

1. Never Apply loading="lazy" to the LCP Element

Lazy loading tells the browser: "Wait until the user scrolls near this image before downloading it." Applying lazy loading to an above-the-fold hero image forces the browser to wait, artificially adding 1 to 2 seconds of delay to your LCP score!

  • Add fetchpriority="high": Hint to the browser's preload scanner to download the hero graphic before lower-priority scripts:
    <img src="hero.webp" fetchpriority="high" width="1200" height="675" alt="Hero">
  • Preload in the <head>: For background images declared in CSS, add:
    <link rel="preload" href="hero.webp" as="image" type="image/webp">
  • Convert to WebP or AVIF: Shrinks image file sizes by 35%–70% compared to legacy PNG/JPEG with zero perceptual loss in clarity.

6. Step 4: Eliminate Render-Blocking CSS and JavaScript

When the browser encounters a <script src="..."> tag without defer or async, it stops rendering HTML completely until that file is downloaded and executed. To fix this:

  • Apply defer to non-critical scripts: Allows HTML parsing to proceed uninterrupted.
  • Inline Critical Above-the-Fold CSS: Extract styles required for the hero section into the <head>, deferring secondary styles asynchronously.
  • Purge Unused CSS & JS Bundles: Strip out unused components from frameworks like Bootstrap, Tailwind, or complex slider libraries.

7. Step 5: Reduce Server Response Time & TTFB

Time to First Byte (TTFB) measures the delay between a visitor requesting a page and receiving the first byte of data from the web server. If your TTFB exceeds 800ms, your LCP can never be under 2.5 seconds. Optimize TTFB by:

  • Implementing Redis or Memcached server-side object caching.
  • Upgrading to PHP 8.3 with OPcache enabled.
  • Deploying an Edge CDN (such as Cloudflare) to serve cached HTML from global server locations closest to the user.

8. Step 6: Fix Interaction to Next Paint (INP) & Layout Shifts

INP replaced FID (First Input Delay) as a mandatory Core Web Vital. It tracks how quickly the browser paints a response frame after a user taps a mobile menu or submits a form. Break up long JavaScript tasks into smaller chunks (<50ms) using requestIdleCallback() or setTimeout(). Prevent layout shifts (CLS) by giving all images and video embeds explicit width and height attributes.

9. How Website Speed Directly Influences SEO Rankings

Google officially incorporates Core Web Vitals into its Search Ranking systems as part of the Page Experience signal. When two websites have equally relevant content on a topic, Google's algorithms favor the site that provides a smooth, sub-second user experience. Furthermore, fast load times decrease crawl latency, allowing Googlebot to index more pages across your site efficiently.

Frequently Asked Questions

What is considered a good Largest Contentful Paint (LCP) time?
Google defines a good LCP score as 2.5 seconds or less for at least 75% of actual real-world page visits. Anything between 2.5s and 4.0s needs improvement, and over 4.0s is considered poor by Google's Page Experience ranking signals.
Does a 90+ Google PageSpeed score guarantee higher search rankings?
No single metric guarantees #1 rankings. Google treats Core Web Vitals as a page experience tiebreaker signal. However, slow loading causes users to bounce quickly, directly harming engagement signals. A fast page combined with high-quality content and authority yields superior long-term ranking stability.
Why is my hero image delaying LCP?
Common culprits include: applying loading="lazy" to above-the-fold images, serving uncompressed PNG/JPEG files instead of WebP/AVIF, rendering the image through a client-side JavaScript slider, or failing to preload it using <link rel="preload"> or fetchpriority="high".
